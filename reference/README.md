# Reference implementation

Everything you need to run a BirdNET Tiny N6 model outside this repository:
the exact audio processing, in one readable file, and test vectors to prove a
port computes the same thing.

| File | What it is |
|---|---|
| [`birdnet_tiny_reference.py`](birdnet_tiny_reference.py) | The specification: audio file → windows → model input → scores → detections. NumPy + SoundFile + TensorFlow Lite, nothing from this package. |
| [`vectors/test_signal.wav`](vectors/test_signal.wav) | A 6 s synthetic recording (24 kHz, mono, PCM16), generated by `make_test_signal()`. |
| `vectors/<bundle>.json` | Every stage of the pipeline on that recording, for each released bundle: per-window sums, ranges and first values of each intermediate, and the model's output. |
| [`../firmware/Src/audio_stft.c`](../firmware/Src/audio_stft.c) | The same hybrid STFT in C, as it runs on the Cortex-M55 (CMSIS-DSP). |

```bash
# Run a bundle on a recording, printing each stage's shapes and ranges
python reference/birdnet_tiny_reference.py --bundle <bundle-dir> --audio recording.wav --explain

# Check this implementation (or yours, see below) against the recorded vectors
python reference/birdnet_tiny_reference.py --bundle <bundle-dir> \
    --check-vectors reference/vectors/<bundle>.json

# Keep every intermediate as .npy for a side-by-side comparison
python reference/birdnet_tiny_reference.py --bundle <bundle-dir> --audio recording.wav --dump stages/
```

A bundle is the unpacked release zip: `*_INT8.tflite`, `*_model_config.json`
and `*_labels.txt` are all the script reads. It needs `numpy`, `soundfile`,
`scipy` (only to resample) and `tensorflow` or `tflite-runtime`.

## The pipeline

Every constant comes from the bundle's `*_model_config.json`. Never hard-code
them; a bundle is free to change them.

| # | Step | `raw` | `hybrid` |
|---|---|---|---|
| 1 | Read mono float32 in [-1, 1] at `sample_rate` | ✔ | ✔ |
| 2 | Windows of `chunk_duration` s, hop `chunk_duration / 2`, last window right-aligned | ✔ | ✔ |
| 3 | Model input | divide by the window's peak → `[samples, 1]` | magnitude STFT → compress → min-max → `[fft_length/2, spec_width, 1]` |
| 4 | Run the INT8 model (float32 in and out), one window at a time | ✔ | ✔ |
| 5 | Sigmoid if `output_activation` is `logit` | ✔ | ✔ |
| 6 | Max over a recording's windows, then threshold | ✔ | ✔ |

The released bundles use 24 kHz, 2.5 s windows and a 1.25 s hop. `raw` takes
60,000 samples. `hybrid` takes a 256 × 384 spectrogram (`fft_length` 512,
`spec_width` 384).

### Step 1: audio

Average the channels and resample to `sample_rate`. The models were trained
with polyphase resampling (`scipy.signal.resample_poly` at the reduced ratio);
any good band-limited resampler stays within the tolerances below. PCM16 is
scaled by 1/32768.

### Step 2: windows

Windows start every `hop = chunk_duration / 2` seconds. The **last window is
right-aligned** to the end of the recording, so the final seconds are scored at
full weight, not zero-padded; a recording shorter than one window is
zero-padded once. With 6 s of audio: starts at 0, 1.25, 2.5 and 3.5 s.

### Step 3, `raw`: peak normalization

`x / (max|x| + 1e-6)`, per window. That is the whole host-side job: the model
computes its own spectrogram with a learned filterbank inside the network, and
on the STM32N6 that runs on the NPU. Do not normalize a `raw` window any other
way; the model is trained on exactly this.

### Step 3, `hybrid`: the spectrogram

1. **Hop from the frame count:** `hop = samples // spec_width`, 156 for
   60,000 samples into 384 frames.
2. **Centered frames:** zero-pad the window by `fft_length / 2` on both sides;
   frame *i* is padded samples `[i·hop, i·hop + fft_length)`, centred on
   original sample *i·hop*.
3. **Periodic Hann:** `0.5 − 0.5·cos(2πn / N)` for `n = 0 … N−1` (divide by
   `N`, not `N − 1`).
4. **Magnitude of the real FFT**, bins `0 … N/2 − 1`: the Nyquist bin is
   dropped. No FFT scaling.
5. **Compress** per `input_compression`: `sqrt` in every released hybrid
   bundle (`log`: natural log floored 80 dB below the window's peak).
6. **Min-max normalize** the whole window's spectrogram:
   `(S − min) / (max − min + 1e-10)`. This also makes the input independent of
   recording gain, so a hybrid window is not peak-normalized.

The output is frequency-major: row = FFT bin, column = frame.

### Steps 4–6: model, output, detections

The INT8 models take and return float32; quantization is internal. Output is
one value per class in the order of `*_labels.txt`. From version 1.5 on,
bundles emit **logits** (`"output_activation": "logit"`): apply
`1 / (1 + e^−x)`, or compare logits against `ln(t / (1 − t))` instead, which is
exact and free (a threshold of 0.5 becomes 0.0). Pool each class over a
recording's windows with **max** — how the models are evaluated — and threshold.
0.5 is the reported operating point; each bundle's model card lists detection
and false-alarm rates at 0.25, 0.5 and 0.75.

## Verifying a port

`vectors/<bundle>.json` records, for every window of `test_signal.wav`:

- `window`: the cut audio,
- `stft_magnitude` and `compressed` (hybrid only): steps 3.1–4 and 3.5,
- `model_input`: what the model is fed,
- `model_output`: its 100 raw outputs (logits),

each as `shape`, `sum`, `min`, `max` and the first eight values in row-major
order, plus the pooled probabilities of the recording. Compare stage by stage
and the first mismatch tells you which step to look at. A faithful port agrees
to about 1e-4 relative on every input stage (float32, a different FFT) and to
within one or two INT8 output steps on the model output (the step is in the
bundle's TFLite, ~0.1 in logits); detections at 0.5 match exactly.

Typical mistakes, in the order they are usually made: a non-centered STFT
(frames start at *i·hop*; the spectrogram is shifted half a frame), a symmetric
Hann window, keeping the Nyquist bin, forgetting the min-max normalization, and
normalizing a whole file instead of each window.

## Where this runs in the firmware

On the STM32N6570-DK (`firmware/`), steps 2, 3 (`raw`), 5 and 6 are plain C on
the Cortex-M55; the model runs on the Neural-ART NPU. The hybrid STFT is
`firmware/Src/audio_stft.c`, built on CMSIS-DSP's Helium FFT; it is compiled
natively and checked against the host implementation by
`tests/test_firmware_stft.py`, and `tests/test_reference_implementation.py`
checks that this reference and the training package build identical model
inputs. Timings per 2.5 s window at the firmware's 400 MHz clock: `raw` 15 ms
on the NPU; `hybrid` 33 ms of STFT on the M55 plus 19 ms on the NPU.

The `raw` model's in-network frontend (learned Gabor filterbank, magnitude,
smoothing) is described in [docs/dev/audio-frontends.md](../docs/dev/audio-frontends.md).
